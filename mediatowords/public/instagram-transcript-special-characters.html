Why do special characters look wrong in my Instagram transcript?

Reopen the original download as UTF-8 before saving another copy. If the accents return, save a new UTF-8 copy. If a later copy already contains literal question marks where letters used to be, go back to the version that still shows the correct words.

One subtitle file, two different failures

We built three short SRT cues containing café, İzmir and 🙂. We saved all three in UTF-8, then made a second copy using Windows-1252 with unsupported characters explicitly replaced by question marks. We reopened each copy using its matching encoding and compared every cue.

The accent in café survived both saves. The dotted capital I and the emoji survived only the UTF-8 save. In the second file each missing character had become the single byte 3F, the question mark itself. The cue numbers and timing lines still matched.

Try the UTF-8 sample and the Windows-1252 sample in your own subtitle editor. Both are constructed test files. The results above measure a save-and-reopen operation, independent of speech recognition.

What if the transcript already has the wrong word before download?

Listen to the cue and check the spelling in the on-screen result. An encoding change can restore the display of existing letters. To change the words themselves, correct the transcript text and export it again.
